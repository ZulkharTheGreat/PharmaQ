# PharmaQ — локальный MVP

Рабочая модель управления производственными отклонениями для пилота одной линии. Next.js 15 / React 19 / TypeScript, статический экспорт, данные и содержимое вложений в IndexedDB. Серверная БД и ключи внешних сервисов не нужны.

## Запуск

Проверено на Windows, Node.js **24.21.0**, npm **11.19.0**.

```powershell
cd C:\Users\acer\Desktop\PharmaQ
npm.cmd ci
npm.cmd run build
npm.cmd start
```

Открыть **http://127.0.0.1:3000**. `npm start` раздаёт готовый `out`, а не вызывает `next start`. Сервер слушает только локальный компьютер. После изменений исходников сборку необходимо повторить. Уже установленным зависимостям повторный `npm ci` не требуется.

Разработка с обновлением при изменении исходников:

```powershell
npm.cmd run dev
```

Dev: **http://127.0.0.1:3100**, каталог `.next-dev` отделён от production. Данные разных портов и профилей браузера независимы. Для другого порта статической версии:

```powershell
$env:PORT = '3200'
npm.cmd start
```

Если порт занят, остановите ранее запущенную версию в её терминале или выберите другой порт. Для прежних данных используйте **тот же протокол, адрес, порт и профиль**, что раньше: `localhost` и `127.0.0.1` имеют разные браузерные хранилища.

## Рабочий процесс

Основных разделов три: **Моя работа**, **Отклонения**, **Отчёты**. Настройки снизу. Дело открывается в правой панели с обзором, документами и историей; длинные формы разворачиваются. Закрытие панели сохраняет контекст реестра.

1. Сотрудник регистрирует факты, обнаружение, место, первичные действия, объекты и файлы. Координатор получает назначение оценки. До подтверждения критичность не оценена.
2. Качество сохраняет черновик или подтверждает оценку: критичность, основания, объекты, участников, руководителя и срок.
3. Назначенный руководитель оформляет факты, гипотезы, доказательства, хронологию и отдельный итог причины. Неподтверждённая причина требует неопределённости и решения качества.
4. Руководитель/качество составляет план мер и проверок эффективности. После двух согласований новая версия вступает в действие; до этого действует прежняя.
5. Исполнитель принимает назначение, начинает и сдаёт результат. Принимающий принимает его или возвращает с замечаниями. Все попытки сохраняются.
6. Эффективность проверяется отдельным заданием после приёмки зависимых мер и периода наблюдения. Отрицательный эффект требует нового содержательного расследования. Дефект работы и отсутствие эффекта — разные решения.
7. Качество закрывает дело с основанием после устранения показанных препятствий. Закрытая запись доступна для чтения; повторное событие регистрируется новым связанным делом.

Первичные меры и уточнения создаются в обзоре → «Задания» до утверждения плана. Маршруты без мер, дубль и вне области доступны в решении о закрытии. Дубль связан с основным делом и сохраняет историю.

Передача требует подтверждения получателя; до него отвечает прежний владелец. Исполнитель и принимающий меняются явно отдельным действием. У подрядчика передача сопровождающего обновляет внутреннего исполнителя, сохраняя независимую приёмку. Отказ передаёт вопрос руководителю; принудительная передача требует основания.

Ожидание содержит причину, зависимость, владельца результата и контрольную дату; возраст и просрочка продолжаются. Перенос сохраняет исходный срок и основания. Плановая отмена проходит через новую версию; зависимости требуют собственных решений. Принятую работу нельзя переписать — создаётся связанная новая мера.

Внешние решения о партии/оборудовании вносятся с автором, датой и документом/ссылкой. Обязательное неполученное решение блокирует закрытие. Программа не принимает производственных решений.

## Хранение, миграция и восстановление

- IndexedDB `pharmaq-local-v2`, схема 2: состояние, Blob-файлы, исходная резервная копия. Данные операции, история и файлы коммитятся одной транзакцией. Ошибка квоты/записи не считается успехом.
- `pharmaq-session` содержит только идентификатор пользователя. Старый объект с email преобразуется без пароля. Отсутствие сессии не вызывает автоматический вход.
- На прежнем адресе при первом открытии читается `pharmaq-deviations`. Исходный ключ **не удаляется**, дополнительно сохраняется в IndexedDB. Повторное открытие использует уже перенесённое состояние.
- Сохраняются номера, исходные поля, комментарии, меры, неизвестные участники. Полная исходная запись доступна в сведениях. Неоднозначности отмечаются. «Просрочено» становится «Уточнить этап» с сохранением прежнего статуса, без вымышленных этапов/дат. Старые закрытые дела не получают вымышленных приёмок.
- Ошибка миграции показывает скачивание оригинала и загрузку исправленного JSON. Восстановление сохраняет обе копии. Повреждённые данные не заменяются демонабором.
- Если нет старых данных и новой БД, создаются 12 демонстрационных дел. Их события построены теми же командами и отмечены как демонстрационные.
- Для **нового пустого** профиля/адреса открыть `/?empty=1`. Параметр не сбрасывает существующие записи. Например: `http://127.0.0.1:3000/?empty=1` при первой установке без примеров.
- Настройки → «Выгрузить данные и файлы»: JSON вместе с байтами файлов и legacy-оригиналом. Admin восстанавливает копию только в пустую базу. Там же импортируется массив записей прежней версии. Для другого адреса сначала выгрузите данные на исходном, затем импортируйте в новый пустой профиль/адрес.
- Очистка данных браузера может удалить IndexedDB. Резервная выгрузка предназначена для переноса и восстановления; облачного хранения нет.
- Вкладки проверяют revision: устаревшее сохранение отклоняется, текст остаётся в форме. При конфликте сохраните нужный текст, обновите данные и примените его повторно. Несохранённый ввод защищён при переходах/закрытии страницы.

## Файлы, время, реестр и отчёты

Файл: непустой, до **20 МБ**, PDF, PNG/JPEG/WebP, TXT/CSV, DOC/DOCX, XLS/XLSX. Проверяются расширение, запрещённые MIME и размер. Blob скачивается после reload. Предпросмотр — для PDF, текста и изображений; Office-файлы скачиваются. Новая версия связана с последней прежней и не удаляет её. Автор/источник отделён от загрузившего. Удаление принятого доказательства через UI не предусмотрено.

Время хранится в UTC, отображается в поясе браузера. Длительности календарные, не рабочие часы и не трудозатраты. Возраст дела не суммируется из параллельных работ. Этапы, ответственность, попытки, проверки и ожидания имеют отдельные интервалы. Фактическое время отличается от внесения. Качество исправляет разрешённые метки с основанием и историей, пока дело открыто. Неизвестные даты не подменяются.

«Мои» — открытые дела, где пользователь координатор, участник активного задания (ответственный/исполнитель/принимающий) или получатель передачи дела. Поиск: название, номер, линия, объекты, серии и коды. Фильтры сочетаются. CSV учитывает весь отбор; столбцы, фильтры и размер страницы сохраняются для пользователя.

Отчёт отбирает дела по регистрации. Без периода учитываются legacy без даты; при отборе дат они исключаются. Среднее закрытие — обычные закрытые дела с известными метками. Выполнение в срок сравнивает приёмку рабочих заданий с первоначальным и текущим сроком; служебные задачи оценки/расследования исключены. Повторы определяются связью дел. Пустые данные не превращаются в вымышленные проценты. CSV скачивается; «Печать / PDF» открывает печать браузера.

Уведомления: назначения, возвраты, передачи, сроки, ожидания и допуски. Проверка при открытии/возврате и раз в минуту в видимой вкладке. По умолчанию предупреждение о сроке за 24 часа, непринятое назначение через 24 часа; admin меняет параметры. При закрытом браузере нет фоновой доставки, email или Telegram.

## Устройство и границы

- `app/page.tsx` — оболочка, сессия, навигация, уведомления и защита ввода; `app/globals.css` — дизайн и адаптивность.
- `components/` — реестр, работа, формы дела/задачи/плана, документы, отчёты и настройки.
- `lib/domain/` — модель, команды, полномочия, переходы, селекторы и время.
- `lib/storage/` — репозиторий, IndexedDB, миграция и резервные копии.
- `lib/demo/` — демоматрица и воспроизводимые примеры; `tests/` — тесты приложения.

`supabase/migrations/001_initial_schema.sql` сохранена как предварительный материал, **не применялась**. Она не соответствует полной новой модели и не является безопасным production backend: исходные RLS-политики и серверные бизнес-проверки требуют отдельной работы. Заполнение `.env.example` не подключает UI к Supabase; переменные старого шаблона локальный MVP не использует.

Промышленное внедрение, защищённый аудит/электронная подпись, серверная авторизация, ERP/LIMS, финансовые операции, портал подрядчика и заводские регламенты не входят в MVP. История отражает команды приложения и не редактируется через UI, но локальную БД можно изменить вне приложения. Контрольная сумма выявляет случайное изменение, а не гарантирует криптографическую защиту.
